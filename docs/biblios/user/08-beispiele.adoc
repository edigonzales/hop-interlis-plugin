== Beispiele

Dieses Kapitel enthält sechs vollständige Mini-Tutorials. Jedes Tutorial besteht aus:

- Einem minimalen INTERLIS-Modell
- Einem Beispiel-Transfer (XTF)
- Einer Pipeline-Beschreibung
- Dem erwarteten Ergebnis

Die mitgelieferten Modelle und Transfers sind die kanonischen INTERLIS-2.4-Beispiele. Die
allgemeine Plugin-Unterstützung für XTF 2.3 und XTF 2.4 bleibt davon unberührt.

[TIP]
====
Alle `.ili`- und `.xtf`-Dateien aus diesem Kapitel liegen unter `docs/biblios/user/examples/` und können per `include::` direkt in die Dokumentation eingebunden werden.
====

**Ziel**: Mehrwertige Struktur (`Qualitaeten`) als Child-Rows lesen, transformieren und zurückschreiben.

==== Modell

[source,interlis]
----
include::examples/liste-modell.ili[]
----

==== Transfer

[source,xml]
----
include::examples/liste-transfer.xtf[]
----

==== Pipeline

. **Auflösen:** `INTERLIS Input` mit `liste-transfer.xtf`
. **Auflösen:** Aktivieren Sie _Keep source object for Structure Explode_ (Advanced)
. **Auflösen:** `INTERLIS Structure Explode` mit Struktur `Qualitaeten`
. **Child-Transform:** Filtern Sie z. B. so, dass nur Qualitäten mit Code `Q100` übrig bleiben
. **Zusammenführen:** `INTERLIS Structure Collect` (Parent-Stream + Child-Stream)
. **Schreiben:** `INTERLIS Output`

[source,text]
----
Input (Parent):
_ili_tid | Name     | _ili_source_object
"g1"     | "Rathaus" | [interlis-object]

Output (Auflösen):
_ili_parent_tid | _ili_index | Code   | Beschreibung          | Pruefdatum
"g1"            | 0          | "Q100" | "Brandschutz geprüft"  | 2024-01-15
"g1"            | 1          | "Q200" | "Statik geprüft"       | 2024-02-20

Nach dem Zusammenführen (Parent):
_ili_tid | Name     | _ili_source_object
"g1"     | "Rathaus" | [updated-interlis-object]
----

[IMPORTANT]
====
Der `INTERLIS Structure Collect` ersetzt immer den vollständigen Strukturinhalt des Parent-Objekts. Entfernte Child-Rows (z. B. durch Filterung) verschwinden auch im Output.
====

[source,interlis]
----
include::examples/rolle-modell.ili[]
----

==== Transfer

[source,xml]
----
include::examples/rolle-transfer.xtf[]
----

==== Pipeline

1. `INTERLIS Input` mit `rolle-transfer.xtf` und Klasse `DemoRolle.Verwaltung.Gebaeude`
2. `INTERLIS Role Join`:
   - Main input: Gebaeude-Stream
   - Lookup input: Gemeinde-Stream (separater `INTERLIS Input`)
   - Rolle: `Gemeinde`
   - Felder hinzufügen: `Name`, `BFS_Nummer`
   - Präfix: `Gemeinde_`

Im 2.4-Transfer ist die einfache Rolle als eingebettete Referenz am Gebäude codiert. Der
Role-Join verbirgt diese XTF-Darstellung und verwendet stattdessen das Feld `Gemeinde_ref`.

==== Ergebnis

[source,text]
----
_ili_tid | Name    | Gemeinde_ref | Geometrie | Gemeinde_Name | Gemeinde_BFS_Nummer
---------|---------|--------------|-----------|---------------|--------------------
"g1"     | "Rathaus" | "gem1"       | [Polygon] | "Solothurn"   | 2549
----

[TIP]
====
Der `INTERLIS Role Join` liest den Lookup-Stream (Gemeinden) in einen In-Memory-Cache. Bei mehr als 500'000 Lookup-Rows wird eine Warnung ausgegeben. Für sehr grosse Referenzdaten sollten Sie stattdessen einen `Stream Lookup`-Transform oder eine Datenbank-Join verwenden.
====

==== Pipeline

1. `INTERLIS Input` mit `bogen-transfer.xtf`
2. Optional: `Select values` (nur um zu zeigen, dass nichts verändert wird)
3. `INTERLIS Output` mit derselben Modell-/Klassen-Konfiguration
4. `INTERLIS Validate` zum Prüfen der Ausgabe

==== Ergebnis

[source,bash]
----
# 2.4-Ausgabe des Writers (gekürzt):
<geom:coord><geom:c1>2600000.0</geom:c1><geom:c2>1200000.0</geom:c2></geom:coord>
<geom:arc><geom:a1>2600050.0</geom:a1><geom:a2>1200050.0</geom:a2>
  <geom:c1>2600100.0</geom:c1><geom:c2>1200000.0</geom:c2></geom:arc>
<geom:coord><geom:c1>2600100.0</geom:c1><geom:c2>1200000.0</geom:c2></geom:coord>
----

[IMPORTANT]
====
Wenn Bögen linearisiert würden, erschiene statt <geom:arc> eine Serie von <geom:coord>-Punkten.
Geprüft werden deshalb Namespace, ARC-Typ und die drei Kontrollpunkte; XML-Präfixe und
Elementreihenfolge sind nicht Teil der Semantik.
====

==== Pipeline

2. `Table Output` (z. B. CSV oder Datenbanktabelle für Fehlerprotokoll)

==== Ergebnis

[source,text]
----
_ili_severity | _ili_message                 | _ili_line   | _ili_class                       | _ili_tid
--------------|-----------------------------|-------------|----------------------------------|----------
"ERROR"       | *enthält Temperaturbereich* | *vorhanden* | "DemoValidierung.Daten.Messung" | "m2"
----

[NOTE]
====
Der `INTERLIS Validate`-Transform benötigt keinen vorherigen Transform. Er validiert direkt eine XTF-Datei und gibt Fehler als Rows aus, die Sie weiterverarbeiten können (z. B. in eine Datenbanktabelle für ein Fehlerprotokoll schreiben). Die Zeilennummer und die genaue Meldungsform hängen vom Validator-Input und der Spracheinstellung ab; bei einem Klassen-Constraint steht der fachliche Constraint-Name in der Meldung, während `_ili_attribute_path` leer bleibt.
====
