== Ihr erstes XTF: Gebäude als GeoPackage

Sie lesen zwei Gebäude aus einem lokalen INTERLIS-2.4-Transfer und schreiben ihre Attribute und Polygongeometrien in ein GeoPackage. Das Beispiel setzt Hop 2.19.0, Java 21, Geometry Type und Vector/Raster voraus.

=== Modell und Daten

Die Dateien `demo-modell.ili` und `demo-transfer.xtf` liegen gemeinsam unter `docs/biblios/user/examples/`.

----
include::examples/demo-modell.ili[]

Die beiden Objekte sind `g1` (Rathaus) und `g2` (Migros), beide im Basket `b1`. Der vollständige Transfer steht in <<beispiel-a,Beispiel A>>.

=== Pipeline öffnen und konfigurieren

Öffnen Sie die mitgelieferte https://github.com/edigonzales/hop-interlis-plugin/blob/main/examples/xtf-to-gpkg/xtf-to-gpkg.hpl[Pipeline `examples/xtf-to-gpkg/xtf-to-gpkg.hpl`]. Sie enthält `INTERLIS Input → Vector Writer`.

Setzen Sie die Pipeline-Parameter `+E2E_INPUT_DIR+` auf das absolute Fixture-Verzeichnis und `+E2E_OUTPUT_DIR+` auf ein vorhandenes Ausgabeverzeichnis. Die Parameter können im Ausführungsdialog gesetzt werden.

Im Input sind folgende tatsächlichen Controls relevant:

[cols="2,3"]
|===
| Control | Wert
| Data file | `+${E2E_INPUT_DIR}/demo-transfer.xtf+`
| Models | `DemoBodenbedeckung` (alternativ `%DATA`)
| Model dirs | `+${E2E_INPUT_DIR}+`; so arbeitet das Tutorial ohne Netzwerk
| Class | `DemoBodenbedeckung.Bodenbedeckung.Gebaeude`
| Reserved fields | `+_ili_tid+` und `+_ili_bid+` aktiviert
| Default SRID | `2056`, passend zu den LV95-Koordinaten dieser Fixture
|===

`Reload model` lädt die Klassenauswahl neu. Die Schema-Vorschau zeigt `+_ili_tid+`, `+_ili_bid+`, `Name`, `Art` und `Geometrie`. Sie dient der Kontrolle der erzeugten Felder.

Im `Vector Writer` sind die Werte:

[cols="2,3"]
|===
| Control | Wert
| File name | `+${E2E_OUTPUT_DIR}/doc-gebaeude.gpkg+`
| Layer name | `gebaeude`
| Geometry field | `Geometrie`
|===

Verwenden Sie für wiederholte Läufe ein leeres Ausgabeverzeichnis. Führen Sie die Pipeline lokal aus. Ein Kommandozeilenlauf aus dem Repository lautet:

[source,bash]
----
mkdir -p /tmp/interlis-demo-output
"$HOP_HOME/hop-run.sh" -r local \
  -f examples/xtf-to-gpkg/xtf-to-gpkg.hpl \
  -p E2E_INPUT_DIR="$PWD/docs/biblios/user/examples" \
  -p E2E_OUTPUT_DIR=/tmp/interlis-demo-output
----

=== Ergebnis prüfen

`doc-gebaeude.gpkg` enthält den Layer `gebaeude` mit zwei Polygonen, den TIDs `g1` und `g2`, den Namen Rathaus/Migros und den zugehörigen Art-Werten. Kontrollieren Sie das GeoPackage etwa in QGIS oder mit `ogrinfo`:

[source,bash]
----
ogrinfo -al /tmp/interlis-demo-output/doc-gebaeude.gpkg gebaeude
----

Der Paket-E2E-Test prüft auch Attribute, Geometriespalte, SRID 2056 und die beiden Geometrien. <<xtf-lesen,Das nächste Kapitel>> erklärt den Input im Detail.
